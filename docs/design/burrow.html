Pi 5 edge: the three Burrows

A fresh Raspberry Pi OS Lite card, one script, one reboot. About 20 minutes per Pi, most of it waiting. The result is a Pi whose operating system cannot be corrupted by a pulled plug, with a small separate data partition that holds every reading as immutable castings.

What you need, per room

  • Raspberry Pi 5 (1 GB or 2 GB is plenty: the whole stack is about 150 MB of RAM) with the official 27 W USB-C supply or any 5 V / 5 A supply.
  • A 32 GB or 64 GB microSD, A1/A2 class. Nothing else storage-wise, on purpose.
  • A short Ethernet cable to the Tunnel's LAN port.
  • Optional and recommended: the official Pi 5 RTC battery (about $5) on the J5 connector. With it, a Burrow that has been off for a week boots knowing the time.
  • A laptop with Raspberry Pi Imager 2.x (1.x cannot customise the current Trixie images) and an SD card reader.

The code lives in the repo under edge/burrow/: github.com/MakerLabKids/wormhole/tree/main/edge/burrow. The README there explains the files; this page is the procedure.

Step 1 · Write the card

  1. Raspberry Pi Imager → Device Raspberry Pi 5 → OS Raspberry Pi OS Lite (64-bit) (under "Raspberry Pi OS (other)") → your card.
  2. Edit settings before writing:
    • Hostname burrow1 (or 2, 3).
    • User worm with a password you will remember. (Not pi; and not the Wi-Fi password.)
    • Wi-Fi: leave unconfigured. The Burrow is wired, and the script turns the radio off.
    • Services: enable SSH, password authentication (or paste your public key).
    • Locale/timezone as you like.
  3. Write. Wait for "verified".

Step 2 · Stop the root partition from eating the card

On first boot, Raspberry Pi OS expands its root partition to fill the card. We want the root to stay small (about 3 GB) so the rest becomes a separate, read-write /data partition. One edit, before the card ever boots:

  1. Eject and re-insert the card. A small FAT volume called bootfs appears.
  2. Open cmdline.txt on it in a plain-text editor. It is one long line.
  3. Delete this token (and the space before it), leaving everything else exactly as it is: 
    init=/usr/lib/raspberrypi-sys-mods/firstboot
    Save. The file must stay a single line with no trailing newline weirdness; Notepad, TextEdit (plain text) and nano are all fine.
  4. Eject.
If you forget (or the token was not there and the card still fills): the setup script detects that there is no free space and falls back to single-partition mode: /data becomes a directory on the root filesystem and the read-only lock is refused, because locking a root that holds the data would defeat the point. Everything else works. To get the real thing, re-image (20 minutes). Current Trixie images handle Imager's user/SSH settings through cloud-init, which is separate from this token, so removing it does not lose your customisation.

Step 3 · First boot and the setup script

  1. Card in, Ethernet to the Tunnel's LAN port, power. Give it two minutes; the first boot generates keys and reboots once.
  2. Find it. Easiest: the Tunnel's admin page → Clients lists burrowN with a 192.168.8N.1xx address. Or from a laptop on the room's WormHole: 
    ssh worm@burrow1.local
  3. Get the code and run the setup (replace the room number): 
    sudo apt-get update && sudo apt-get install -y git
git clone https://github.com/MakerLabKids/wormhole.git
cd wormhole/edge/burrow
sudo ./setup-pi.sh 1
    It takes about five minutes with an internet uplink through the Portal. (No internet yet? It needs apt for chrony and parted; everything else is offline. Do this step somewhere with Wi-Fi, or tether the Portal to a phone.)
  4. Near the end the script moves the Pi to its fixed address, so your SSH session may freeze. Reconnect: 
    ssh worm@192.168.81.10
    (82 or 83 for the other rooms).

Step 4 · Verify

curl -s http://192.168.81.10:8080/health
# {"ok":true,"edge":"burrow1","room":1,"ts":...,"clk":"free","version":"0.1.0"}
curl -s http://192.168.81.10:8080/api/status | python3 -m json.tool | head -40
sudo journalctl -u burrow -n 20 --no-pager
  • From a phone on the room's WormHole: http://192.168.81.10:8080/ shows the (empty) dashboard.
  • clk will say free until chrony has agreed with a peer or the internet; that is expected on a lone first Burrow. It becomes peer when a second Burrow is up, ntp when the Portal has an uplink.
  • No Picos yet? Pretend: from your laptop, python3 edge/burrow/tools/simbins.py --edge http://192.168.81.10:8080 --n 5 --once and five fake bins appear.
  • Peers: /api/status → peers shows burrow2/burrow3 as unreachable until they exist. That is fine.

Step 5 · Cloud link (after the Cloudflare page)

Two small files and one package. Do this before locking, or unlock first (below).

echo 'the-burrow1-edge-token'   | sudo tee /etc/burrow/cloud.token
echo 'the-shared-live-key'       | sudo tee /etc/burrow/live.key
sudo chgrp burrow /etc/burrow/cloud.token /etc/burrow/live.key
sudo chmod 640   /etc/burrow/cloud.token /etc/burrow/live.key
sudo systemctl restart burrow
sudo /opt/burrow/install-cloudflared.sh 'eyJ...the tunnel token for burrow1...'

The tunnel runs HTTP/2 over TCP 443 only, so it works through anything a browser works through. Check: curl -s http://192.168.81.10:8080/api/status | grep -o '"reachable": *[a-z]*' says true within a minute of the Portal having internet, and systemctl status cloudflared shows "Registered tunnel connection".

Step 6 · Lock it

sudo /opt/burrow/burrow-lock.sh

This adds the overlay module to the initramfs (Trixie needs that or the overlay silently does nothing), enables the overlay root and the read-only boot partition through raspi-config, and reboots. From now on the OS lives in RAM on top of a read-only card; only /data is written. Verify after the reboot:

findmnt /            # FSTYPE overlay
sudo touch /etc/x    # Read-only file system
touch /data/x && rm /data/x   # works
systemctl status burrow
Changing anything later (code update, new token, apt): sudo /opt/burrow/burrow-unlock.sh (reboots writable) → make the change (for code: cd ~/wormhole && git pull && sudo edge/burrow/install.sh) → sudo /opt/burrow/burrow-lock.sh. The data partition is untouched by lock and unlock.

Replacing a dead Burrow

Same six steps with a new card, same room number, same address. The moment it is up, it pulls every casting the other two Burrows hold (all three rooms' history) and resumes. The only data that can be lost with a dead card is the room's unsealed open log: at most the last 15 minutes before the failure, and only if the Picos' own 24-hour RAM graphs are not consulted. The cloud, if it was reachable at any point, already has everything older.

If the card is fine and the Pi died, move the card. Nothing on it is tied to the board.

About the clock

  • The Pi 5 has a real-time clock. Without the battery it keeps time only while powered; after a power cut it boots with the time it last saved, which could be hours or days behind.
  • chrony fixes it from the internet when there is any (the Portal's uplink), or agrees with the other Burrows (orphan mode elects one as the reference). The Burrow service also steps the clock itself if the cloud answers with a time more than 60 s away while chrony has no source.
  • Every row records clk = ntp, peer or free, so a later reader knows how much to trust a timestamp. The dashboard shows it as a badge.
  • With the battery fitted, also add dtparam=rtc_bbat_vchg=3000000 to /boot/firmware/config.txt (while unlocked) so the Pi trickle-charges it, and check with sudo hwclock -r.
