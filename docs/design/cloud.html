Cloudflare: the Surface at whs.makerlabkids.com

One Worker, one D1 database, one R2 bucket, three tunnels, all on the free plan. About 30 minutes, most of it copying values from one place to another. The code is in cloud/surface/ and its README has the same commands without the commentary.

Before you start

  • makerlabkids.com is a zone in your Cloudflare account (it is). The Worker's custom-domain route creates the whs DNS record itself; do not pre-create it.
  • Node 20+ on your laptop. cd cloud/surface && npm i installs Wrangler 4 locally.
  • The free plan is enough for everything below. The budget shows where the numbers land.
  • What the Worker does, in one breath: accepts snapshots, castings and rollups from the Burrows (bearer tokens), verifies castings by reading them back from R2, serves the dashboard and its API to logged-in students (cookie sessions, team passphrases), logs who looked, and proxies live server-sent events from the Burrows' tunnels.

Step 1 · Database, bucket, secrets, deploy

  1. Log Wrangler in: 
    cd cloud/surface
npm i
npx wrangler login
  2. Create the database and load the schema. The create command prints a database_id; paste it into wrangler.jsonc where it says REPLACE_ME. 
    npx wrangler d1 create wormhole
#  edit wrangler.jsonc -> "database_id": "<the id it printed>"
npx wrangler d1 execute wormhole --remote --file schema.sql
  3. Create the bucket: 
    npx wrangler r2 bucket create wormhole-castings
  4. Generate and store the secrets. The helper prints everything once and, with --put, also pushes the four Worker secrets. Keep the printed output (a password manager entry): it has the three Burrow tokens and the live key you will type onto the Pis. 
    tools/gen-secrets.sh --put
    SecretUsed for
    SESSION_SECRETsigns the wh_session cookie
    EDGE_TOKENSJSON map of Burrow name → bearer token; each Pi gets its own line in /etc/burrow/cloud.token
    LIVE_KEYsent by the Worker on /live to the tunnels; the same value goes in /etc/burrow/live.key on every Pi
    ADMIN_BOOTSTRAPone-time password that lets you create the first admin account
  5. Deploy: 
    npx wrangler deploy
    The first deploy creates whs.makerlabkids.com. Open it: you get the dashboard's login screen (nothing to log into yet).
Check: curl -s https://whs.makerlabkids.com/v1/edge/ping -H 'authorization: Bearer <the burrow1 token>' returns {"ok":true,"ts":…}. Without the header it returns 401.

Step 2 · The first admin, teachers, and the teams

  1. Create your admin account (works only while no admin exists): 
    curl -sS https://whs.makerlabkids.com/api/admin/bootstrap \
  -H 'content-type: application/json' \
  -d '{"name":"quincy","password":"<a real password, 8+ chars>","bootstrap":"<ADMIN_BOOTSTRAP>"}'
  2. Log in on the website with that name and password. The Admin link appears in the header.
  3. Teachers: Admin → Teams → create with role teacher and a real password. Teachers see everything and the visitor logs but cannot change teams.
  4. Teams: the roster you built on the Pico fleet page is already the right CSV: its first four columns are team,period,bin,room. Admin → Teams → Import CSV, paste: 
    cut -d, -f1-4 tools/fleet/roster.csv
    (60 rows per paste; do it in two batches.) The reply lists each team's three-word passphrase once. Use the "print cards" button right away: one card per team with name, period, bin, passphrase and the URL. Reset a passphrase any time from the same tab; it invalidates that team's sessions.
  5. Students log in with: their team from the dropdown, the passphrase from the card, and their first name. The first name is what shows up in the visitor log. Sessions last the semester.
Why not Cloudflare Access or Google? Access's free tier stops at 50 users, students have no school Google accounts, and 52 groups is too many shared passwords to manage by hand. Team passphrases plus a typed first name give per-visit attribution at zero cost, and a leaked passphrase is one reset away from fixed.

Step 3 · Three tunnels (the live path)

Each Burrow runs cloudflared as an outbound-only HTTP/2 connection to Cloudflare; the Worker reaches a Burrow's live stream through it. Nothing is opened on the school network.

  1. Cloudflare dashboard → Zero Trust (one.dash.cloudflare.com; the free Zero Trust plan is fine, you will not use any of its seats) → Networks → Tunnels → Create a tunnel → Cloudflared → name it burrow1.
  2. On the install page, pick Debian · arm64. Do not run the commands it shows; copy only the long token that follows service install. Save it with your secrets as the burrow1 tunnel token.
  3. Public Hostnames → Add: subdomain burrow1.whs, domain makerlabkids.com (so the hostname is burrow1.whs.makerlabkids.com, which is what the Worker's TUNNEL_DOMAIN setting expects). Service type HTTP, URL localhost:8080. Save.
  4. Repeat for burrow2 and burrow3.
  5. On each Pi (unlocked), from the Pi 5 page: 
    sudo /opt/burrow/install-cloudflared.sh '<that Pi's tunnel token>'
    The script pins --protocol http2 so it only ever uses TCP 443.
Check: the Zero Trust tunnel list shows all three Healthy whenever the Portal has internet. curl -s https://burrow1.whs.makerlabkids.com/health returns 403 (the Burrow refuses tunnel requests without the live key: correct). Logged in on the dashboard, the Live page shows a green dot for each room whose Burrow is online.

Step 4 · Tell the Pis

On each Burrow, with the values from gen-secrets.sh:

echo '<burrowN token>'  | sudo tee /etc/burrow/cloud.token
echo '<LIVE_KEY>'       | sudo tee /etc/burrow/live.key
sudo chgrp burrow /etc/burrow/cloud.token /etc/burrow/live.key
sudo chmod 640   /etc/burrow/cloud.token /etc/burrow/live.key
sudo systemctl restart burrow
curl -s http://localhost:8080/api/status | python3 -c 'import json,sys; c=json.load(sys.stdin)["cloud"]; print(c["reachable"], c["error"])'

Within a minute the dashboard at whs.makerlabkids.com shows that room's bins, and within 20 minutes the first casting flips to verified (Admin → Castings, or /api/status → store.unverified going down on the Pi).

Updating and local development

  • Code change → npx vitest run (23 tests inside a real local workerd with local D1 and R2) → npx wrangler deploy. Secrets and data survive deploys.
  • Schema change → add statements to schema.sql (keep them IF NOT EXISTS / additive) and re-run the d1 execute line.
  • Laptop: npx wrangler dev -c wrangler.local.jsonc runs the whole Worker locally with dummy tokens (tok1…) and a bootstrap password of bootstrap-me; point a laptop Burrow's cloud.url at it. Details in the README.
  • Costs to watch: Workers → Metrics shows requests/day (limit 100k) and D1 → the database → rows written/day (limit 100k). Both should sit well under half.
